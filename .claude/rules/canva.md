# Canva を操作するとき（Canva MCP）

2026-09-26 のセミナー告知バナーの作業で分かった、Canva MCP の癖をまとめたもの。
どのバナーがどの告知に使われているかは、その回のファイル（`セミナーLP文面/{開催日}_{slug}.md`）の「告知物」。

## 文字

- **`add_text` で足した文字は、書体を選べず Canva の標準の書体になる**（`format_text` でも書体は変えられない）。
  バナーの太い書体を保ちたいときは、**既存の文字要素を `replace_text` で書き換えて使い回す**。
  新しく足すのは、ラベルなど標準の書体で困らないものだけにする
- **標準の書体には「〜」が無い**（豆腐になる）。標準の書体の文字では「~」を使う。
  既存の太い書体（`YAFdJiHXlcI`）には「〜」がある
- 文字の大きさ（`font_size`）は整数しか渡せない
- **小見出しや日付の書体（`YACgEZ1cb1Q`）は、描く経路で和文の見え方が変わる。** 編集画面では太いが、PNG でダウンロードすると和文だけ細い別の書体になる
  （症状の記録は `アプリ化実装状況.md` §6）。書体の設定を変えていなくても起きるので、受け取った画像は置く前に既存の OG画像と見比べる

## 編集の流れ

- `read-design` を `open_transaction: true` で開き、`edit-design` で直し、**サムネイルで仕上がりを確かめてから** `commit` する
- 1回の `edit-design` にまとめて操作を渡せる。位置や大きさを決めてから、まとめて流すと速い
- **MCP の接続が切れると、開いていた編集は無効になる。** 「transaction が無い」と言われたら `read-design` で開き直し、
  直す前の状態から操作をやり直す
- 保存（`commit`）は取り消せない。ユーザーが内容を決めた変更だけを保存する

## ページを組み替える（merge-designs）

- **1回の呼び出しで渡せる操作は1つだけ。** 別のデザインからページを差し込むときは、差し込み元ごと・並びの切れ目ごとに呼び分ける
- **エラー（`version conflicted`）が返っても、少し遅れて反映されることがある。** 再試行すると同じページが二重に入る。再試行の**あと**に返ってくる `page_count` が想定どおりかを見て、増えすぎていたら `delete_pages` で消す（症状の記録は `アプリ化実装状況.md` §6）
- 差し込んだページには差し込み元の発表者メモも付いてくる。文字と一緒にメモも書き換える

## サイズ違いを作る

- `resize-design` は新しいデザインを作るが、**配置は組み直さない**（元の配置が縮小されて真ん中に置かれるだけ）。
  文字・枠・背景を1つずつ `resize_element` と `position_element` で置き直す
- イラストのように複数の図形でできているものは、**`group_elements` でまとめてから** `resize_element`
  （`preserve_aspect_ratio: true`）で拡大し、`position_element` で動かす
- 作ったら `update_title` で用途が分かる名前にする（`resize-design` は元と同じ名前のまま作る）

## 図形でドット絵を描く

- **`insert_shape` でドット絵を描ける**（2026-11-05 の 11/18 横長）。`view_box` をマスの数（例 64×42）にして、**色ごとに1つの図形**を同じ位置・同じ大きさで重ねる。
  パスは横に続くマスを `M{x} {y}H{x2}V{y+1}H{x}Z` でまとめると短くなる（64×42 の絵で 20 色・合わせて約 5,000 字。1回の `edit-design` で流せた）
- 先に手元の Python（Pillow）で格子を描いて PNG で見た目を確かめ、そこからパスを書き出す。直すときは色の図形ごとに `replace_shape` で差し替えられる
- 図形は後から入れたものほど前に出る。既存の文字の上に枠（ウィンドウ）を足したら、文字を `layer_element`（`front`）で前に出す。`back` にすると全面の地の図形より後ろに回って見えなくなる

## 画像生成（generate-image）

- **プロンプトに実在のゲーム機や商品の名前が入ると、そのロゴや機械の形をそのまま描いてくる。人を含めると実写風の顔になる**（2026-11-05。「任天堂64・PS2」などを含む指示で、実写風の男性と実在のロゴが入った）。
  告知物に使えないので、そういう絵は図形で描くか、名前を含まない指示で作る（この道具はユーザーの言葉をそのままプロンプトにする決まりがある）

## ユーザーにリンクを渡す

- **デザインIDから組み立てた `https://www.canva.com/design/{ID}/edit` は、ユーザーの側でエラーになる**（2026-11-04）。
  渡すリンクは `read-design`（`design_metadata`）や `list-folder-items` が返す `edit_url`（`https://www.canva.com/d/...`）をそのまま使う

## 画像の書き出し

- `export-design` は書き出せるが、**この環境からはその URL（`export-download.canva.com`）を取れない**（ネットワーク設定で遮断）。
  リポジトリに画像を置くときは、ユーザーに書き出してもらいチャットで受け取る
- WebP で届いたら `pip install pillow` で PNG に変換する（PyPI は通る）。OG画像は 1200 幅にそろえる
