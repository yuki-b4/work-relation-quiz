# 回答収集＋ガイド自動配信のセットアップ（Google Apps Script）

`prototype.html` の診断結果を Google スプレッドシートに記録し、深掘り申込者に「3日間の読み解きガイド」を自動配信するための、Apps Script Web App のセットアップ手順です。

## 全体像

```
prototype.html  ──fetch(POST)──▶  Apps Script Web App  ──行追加 / 行更新──▶  回答ログ（スプレッドシート）
                                        │
                                        ├─ 申込（guide:true）→ Day1 を即時送信
                                        ├─ 毎朝8時トリガー → Day2・Day3 を送信（ガイド文面シートから組み立て）
                                        └─ ?action=unsub → 配信停止
```

ファイル構成：
- `Code.gs` … 回答の記録（doPost）とルーティング（doGet）
- `Guide.gs` … ガイド配信エンジン（guide-3day-spec.md §9 の実装）
- `GuideContent.gs` … 文面シード（**自動生成。手で編集しない**。`gen_guide_content.py` で `guide-3day-spec.md`＋`ガイド文面24本.md` から再生成）

- 回答ログ: [職場の人間関係タイプ診断_回答ログ](https://docs.google.com/spreadsheets/d/1J9sfu2F3uJtpriORSkz7v-5uNQHD6mR4j3UZ22H1Q7M/edit)
  - 記録先タブは `指標v2`（`Code.gs` の `SHEET_NAME`。存在しなければ自動作成）。精度でなくエンゲージメント／拡散を測る新アンケート用で、旧 `20260619~` とは別管理。
- 追加ライブラリ・外部サービスは不要、無料。

## デプロイ手順（1回だけの作業）

1. <https://script.google.com> を開き、**「新しいプロジェクト」** を作成する。
2. デフォルトの `myFunction` を消し、[`Code.gs`](./Code.gs) の中身を **全部コピペ** する。さらに「＋ ▶ スクリプト」でファイルを2つ追加し、[`Guide.gs`](./Guide.gs) と [`GuideContent.gs`](./GuideContent.gs) の中身をそれぞれコピペする（既存プロジェクトがある場合は `Code.gs` を差し替えて2ファイルを追加）。
3. 保存する（プロジェクト名は任意。例：「人間関係診断 回答収集」）。
4. 右上 **「デプロイ」▶「新しいデプロイ」** を選ぶ。
5. 種類の歯車から **「ウェブアプリ」** を選択し、以下を設定：
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**
6. **「デプロイ」** を押し、初回は **承認** する
   （自分の Google アカウントを選択 →「詳細」→「（プロジェクト名）に移動」→「許可」）。
7. 表示される **「ウェブアプリのURL」** をコピーする
   （`https://script.google.com/macros/s/.../exec` の形式）。

## URLを反映する

コピーした URL を Claude に伝えるか、`prototype.html` の先頭付近にある定数に貼り付けてください。

```js
const SHEET_ENDPOINT = 'ここにウェブアプリのURL';
```

空のままだと送信は行われず、診断の体験だけができます（回答は記録されません）。

## 動作確認

- **エンドポイント単体**：ウェブアプリのURLをブラウザで開くと `{"ok":true,...}` が表示される。
- **通し**：`prototype.html` を開いて診断を最後まで回すと回答ログに1行追加され、3日間ガイドの申込（メール＋許諾）を送るとその行のメール列とガイド配信記録が埋まる。※検証アンケート（5問）は2026-07-20に廃止（フロントから削除。シートの旧アンケート列はそのまま残るが、以後は埋まらない）。

## ガイド自動配信のセットアップ（1回だけの作業）

1. スクリプトエディタで関数 **`setupGuideDelivery`** を選んで実行する（初回は承認が必要）。これで、
   - 回答ログに配信記録列（`guide_day1_at`〜`optout_at`・`ガイドトークン`）が追加され、
   - **「ガイド文面」シート**（共通ガワ9行＋タイプ別24行）と**「ガイド設定」シート**が作成・投入され、
   - **毎朝8時の日次トリガー**が登録される。
2. **「ガイド設定」シートの `value` 列**を実際の値に書き換える：
   - `sender_name`（送信者名）／`sender_contact`（フッターの連絡先表示）／`sender_signature`（Day3署名）
   - `quiz_url`（診断URL）／`survey_url`（アンケートフォームURL）／`webapp_url`（このWebアプリのURL。配信停止リンクに使う）
3. **テスト送信**：エディタで `sendGuideTest('自分のメール', 'OBL')` を実行すると、3通まとめて届く（ログには記録されない）。
4. **通しテスト**：`prototype.html?mode=lead` から自分のメールで申込 → Day1が即時に届く → 翌朝8時にDay2（待てない場合は `sendGuideDailyBatch` を手動実行。ただし日数条件があるため、検証時は回答ログの `guide_day1_at` を前日の日付に書き換えてから実行する）→ フッターの配信停止リンクで `optout_at` が記録されることを確認。

### 運用メモ

- **文面の修正は「ガイド文面」シートを直接編集**すればよい（コード変更・再デプロイ不要）。行の意味：`common` 行＝共通ガワ（`day` × `block`。`day=0` の `footer` は全日共通）、タイプ行＝`type_code` × `day` の本文と件名。メールは `opening → 本文 → education →（closing / cta）→ footer` の順に区切り線で連結される。
- **β期→M4の切替**は、「ガイド文面」シートの `common / day=3 / cta` 行の本文を読み解きセッション案内に差し替えるだけ（guide-3day-spec.md §8）。
- 送信は `MailApp`（テキストメール）。Gmail無料枠は**1日約100通**。バッチは枠が尽きたら安全に中断し、翌朝のトリガーで続きから再開する。
- Day1の即時送信が失敗した行（一時的なエラー等）は、翌朝のバッチが自動でリトライする。

## 2つのモード（URLで出し分け）

`prototype.html` は同じファイルのまま、URLパラメータで対象を切り替えます。

- **検証モード（8名＝過去客向け）**：プレーンなURL。※検証アンケート5問は2026-07-20に廃止（フロントから削除）。モード名はログの `モード` 列の値（feedback/lead）として残る。
- **紹介モード（紹介者向け）**：`?ref=<紹介者コード>` 付きURL（または `?mode=lead`）。3日間ガイドの申込（**メール＋許諾のみ**。guide-3day-spec.md §9で簡素化）を表示・記録し、`ref` で紹介元（コード）も残す。コードは別タブ `紹介者マスタ` で名前に逆引きする（下記）。
  - 例：`prototype.html?ref=TKtp46k`（田中さん用の紹介リンク）
  - 申込があると `guide:true` が送られ、3日間の読み解きガイドが自動配信される（手動送信ゼロ）。

## 紹介者コード → 名前の自動変換（紹介者マスタ）

`?ref=` には紹介者の**名前ではなくコード**（イニシャル＋英数字5文字）を入れる。URLに名前が出ず、ログ側でコード→名前に逆引きする。

**セットアップ（1回だけ・スプレッドシート操作）**

1. 回答ログに新タブ **`紹介者マスタ`** を作成：`A1`＝`コード`、`B1`＝`紹介者名`。2行目以降に「コード｜紹介者名」を記入（例：`TKtp46k｜田中`）。
2. 記録タブ **`指標v2`** の **`AB1`** に `紹介者名`、**`AB2`** に次式を貼る（`C`列＝`紹介元`＝コード。`AB`列に名前が自動表示され、新しい回答行も自動変換）：

   ```
   =ARRAYFORMULA(IF(C2:C="","",IFERROR(VLOOKUP(C2:C,紹介者マスタ!A:B,2,FALSE),"未登録")))
   ```

**コードの形式**：`イニシャル（英大文字）＋ ランダム英数字5文字`（例：田中 → `TK`＋`tp46k`＝`TKtp46k`）。ランダム部はURLから名前を推測されないための不透明化。VLOOKUPは大文字小文字を区別しないので、大小だけ違うコードは作らない。

**使い方**：田中さん用リンク `…/?ref=TKtp46k` から来た回答は `紹介元=TKtp46k` で記録され、`紹介者名` 列に `田中` が自動表示される。未登録コードは `未登録`。

## 記録の流れ（2フェーズ）

回答ID（`回答ID` 列）をキーに、診断とアンケートを同じ行へまとめる。

1. **診断完了時**（`action: create`）：`回答ID` つきの行を追加する。アンケート未回答でも診断結果は取りこぼさない。
2. **アンケート回答時**（`action: update`）：`回答ID` で同じ行を探し、アンケート列だけを埋める。

## 記録される項目

タイムスタンプ／モード／紹介元／9問の回答（極）／3軸の判定（本音・衝突・重心）／タイプコード・タイプ名／5軸スコア／旧・検証アンケート5問の列（2026-07-20廃止。列は互換のため残すが以後は空）／メールアドレス・自由記述／回答ID／立場。

## 法人リード（法人LPの商談フォーム）

`lp-corporate.html` の商談フォームは `action: corpLead` で同じエンドポイントに送信され、回答ログの **「法人リード」シート**（無ければ自動作成）に1行追加されます。

- 記録される項目：タイムスタンプ／メールアドレス／課題（チェックボックスの選択を「、」連結）／自由記述／紹介元（`?ref=`、既定 `corp-lp`）／流入ページ／リードID。「対応状況」「メモ」列は手入力用。
- **corpLead 対応版の `Code.gs` を再デプロイするまで**は、旧コードが `create` 扱いで受けるため、`指標v2` シートに `モード=corp-lead`・メールアドレス・自由記述（課題を連結したもの）として記録されます（リードは失われません）。再デプロイ後から「法人リード」シートに入ります。

## 注意

- **コードを修正したら必ず再デプロイ**：「デプロイ ▶ デプロイを管理 ▶ 鉛筆 ▶ バージョン＝新バージョン」で更新しないと反映されません。
- アクセスを「全員」にするため URL は公開扱いです。8名検証では問題ありませんが、不特定多数に広く配る段階になったら合言葉トークン等での保護を追加してください（必要なら対応します）。
